# 백엔드 구조 — 패키지 설계와 계층 규칙

**관련 문서:** [README](../README.md) · [01_기획.md](01_기획.md) · [02_UI_UX설계.md](02_UI_UX설계.md)

> [01_기획.md §4 시스템 아키텍처](01_기획.md#4-시스템-아키텍처)의 MVC 흐름을 실제 패키지/클래스 단위로 풀어 쓴 것이다.
> 구현 시작 전에 구조를 먼저 고정해, 파일을 아무 데나 만들며 시작하지 않기 위한 문서다.

---

## 1. 패키지 구조

```
com.securebulletinboard
├─ SecureBulletinBoardApplication.java   부트스트랩
│
├─ config/
│  ├─ SecurityConfig.java                Spring Security 설정 (필터체인, PasswordEncoder)
│  └─ WebConfig.java                     (선택) 인터셉터·포매터 등 웹 공통 설정
│
├─ user/                                  회원 도메인
│  ├─ User.java                          엔티티
│  ├─ UserRepository.java                JpaRepository<User, Long>
│  ├─ UserService.java                   가입/비밀번호 변경 로직
│  ├─ CustomUserDetailsService.java      Spring Security UserDetailsService 구현
│  ├─ CustomUserDetails.java             UserDetails 구현체 (userId 노출용)
│  ├─ controller/
│  │  └─ AuthController.java             /signup, /login(뷰만), /account/password
│  └─ dto/
│     ├─ SignupRequest.java
│     └─ PasswordChangeRequest.java
│
├─ post/                                  게시글 도메인
│  ├─ Post.java                          엔티티 (author: User FK)
│  ├─ PostRepository.java                JpaRepository<Post, Long>
│  ├─ PostService.java                   CRUD + 작성자 본인 확인
│  ├─ controller/
│  │  ├─ PostViewController.java         화면(Thymeleaf) 반환용: /, /posts/{id}, /posts/new 등
│  │  └─ PostApiController.java          REST API: /api/posts/**
│  └─ dto/
│     ├─ PostCreateRequest.java
│     ├─ PostUpdateRequest.java
│     └─ PostResponse.java
│
├─ common/
│  ├─ exception/
│  │  ├─ PostNotFoundException.java
│  │  ├─ DuplicateEmailException.java
│  │  └─ GlobalExceptionHandler.java     @ControllerAdvice — 예외 → 응답/에러 페이지 매핑
│  └─ BaseTimeEntity.java                createdAt/updatedAt 공통 (@MappedSuperclass)
│
└─ resources/
   ├─ templates/                          Thymeleaf (layout/, post/, user/ 하위 구성)
   ├─ static/                             css/js (Bootstrap는 WebJars 또는 CDN 대신 로컬 번들 검토)
   ├─ application.yml                     공통 설정
   ├─ application-local.yml               로컬 개발 프로파일
   └─ application-prod.yml                운영 프로파일 (Supabase 접속 정보는 환경변수로 주입)
```

> **도메인 패키지(`user/`, `post/`) 우선, 계층 패키지(`controller/`, `service/`) 차선.** 계층별로 나누면(`controller/`, `service/`, `repository/`를 최상위에 두는 방식) 파일이 늘어날수록 어떤 기능인지 패키지 이름만으로 알기 어려워진다. 이 프로젝트 규모(회원 + 게시글 두 도메인)에서는 도메인별로 묶고, 그 안에서만 `controller/`, `dto/`로 나눈다.

## 2. 계층 간 의존 방향 (반드시 지킬 것)

```
Controller ──▶ Service ──▶ Repository ──▶ DB
     │              │
     ▼              ▼
   DTO            Domain(Entity)
```

- **Controller는 Entity를 직접 반환하지 않는다.** 항상 DTO(`PostResponse` 등)로 변환해서 내보낸다 — Entity를 그대로 노출하면 연관관계(예: `User` 전체, 비밀번호 해시 포함)까지 JSON에 실릴 위험이 있다.
- **Repository는 Controller에서 직접 호출하지 않는다.** 반드시 Service를 거친다 — "본인 글만 수정 가능" 같은 검증이 Service에 있으므로, 이를 건너뛰고 Repository를 직접 쓰면 인가 로직이 통째로 우회된다.
- **역방향 의존 금지**: Repository가 Service를, Service가 Controller를 알아서는 안 된다.

## 3. 인증/인가가 실제로 흐르는 경로

[01_기획.md §7](01_기획.md#7-보안-요구사항)에서 설명한 "이중 방어"를 클래스 단위로 표시하면:

```
1. 요청 도착
   → SecurityConfig의 SecurityFilterChain이 CSRF 검증 → 인증 여부 확인

2. 인증된 사용자 식별
   → CustomUserDetailsService.loadUserByUsername()이 User를 조회해 CustomUserDetails 생성
   → Controller 메서드 파라미터로 @AuthenticationPrincipal CustomUserDetails principal 주입

3. 메서드 단위 인가 (1차 방어)
   → @PreAuthorize("isAuthenticated()") 등으로 로그인 자체가 필요한 엔드포인트 차단

4. 리소스 단위 인가 (2차 방어, 가장 중요)
   → PostService.update(postId, request, principal.getUserId()) 내부에서
     post.getAuthorId().equals(currentUserId) 확인
   → 불일치 시 AccessDeniedException → GlobalExceptionHandler가 403으로 변환
```

**4번을 빼먹으면** "다른 사용자 글 ID로 PUT 호출 시 403" 검증([검증안내서.md](../검증안내서.md))이 실패한다 — 이 프로젝트에서 가장 자주 발생할 수 있는 실수이므로 PostService 구현 시 최우선으로 테스트한다.

## 4. 예외 처리 전략

| 예외 | 상황 | HTTP 상태 |
|---|---|---|
| `PostNotFoundException` | 존재하지 않는 글 ID 조회 | 404 |
| `DuplicateEmailException` | 이미 가입된 이메일로 회원가입 시도 | 409 |
| `AccessDeniedException` (Spring Security 표준) | 본인 글이 아닌 리소스 수정/삭제 시도 | 403 |
| `MethodArgumentNotValidException` (Bean Validation 표준) | 요청 DTO 검증 실패(제목 누락 등) | 400 |

`GlobalExceptionHandler`(`@ControllerAdvice`)에서 API 요청(`/api/**`)은 JSON 에러 응답으로, 화면 요청은 에러 페이지(`error/403.html`, `error/404.html`)로 분기한다.

## 5. 설정 파일 분리

| 파일 | 용도 |
|---|---|
| `application.yml` | 프로파일 공통 설정 (JPA 기본 옵션 등) |
| `application-local.yml` | 로컬 개발용 — Supabase 개발용 프로젝트 또는 로컬 Postgres 접속 정보 |
| `application-prod.yml` | 운영용 — 접속 정보는 파일에 직접 쓰지 않고 `${DB_URL}`, `${DB_PASSWORD}` 형태로 환경변수 참조 (배포처는 [05_배포.md](05_배포.md) 참고, 아직 미확정) |

비밀번호·API 키가 포함된 프로파일 파일은 `.gitignore`에 등록하거나, 값 자체를 환경변수로만 주입해 저장소에 평문으로 올라가지 않게 한다.
