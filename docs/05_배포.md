```bash

./gradlew test        # 36건
npx newman run postman/Secure_Bulletin_Board.postman_collection.json -e postman/Local.postman_environment.json
```

- **DB**: H2 인메모리 (`ddl-auto: create-drop`) — 재시작하면 데이터가 사라진다. 로컬 개발에서는 의도된 동작이다
- **화면**: Thymeleaf가 서버에서 렌더링. Bootstrap도 `src/main/resources/static/css/`에서 서빙하므로 외부 의존이 없다

## 2단계: 배포 (필요해지면)

### 배포처 선택 — 무료로 가능하다

| 항목 | 로컬 | 배포 | 비용 |
|---|---|---|---|
| 앱 (Spring Boot + Thymeleaf) | localhost:8080 | **Google Cloud Run** | **무료** (월 200만 요청·360k GB-초·180k vCPU-초, 기간 제한 없음) |
| DB | H2 (인메모리) | **Supabase** 또는 **Neon** (PostgreSQL) | **무료** |

**왜 Cloud Run인가**

- **상시 무료**다. AWS·Azure의 무료 티어는 12개월 한정이라 포트폴리오용으로는 시한부다
- **요청이 없으면 0으로 줄어든다.** 포트폴리오처럼 접속이 뜸한 서비스에 유리하다
- Render 무료 티어도 쓸 수 있지만 **15분 미사용 시 슬립**되고 깨어나는 데 약 1분이 걸린다. 면접관이 링크를 눌렀을 때 1분을 기다리게 된다

> **후보에서 빠진 것들**
> - **Fly.io**: 이전 문서에서 월 $3-5로 추천했으나, Cloud Run이 무료면서 더 낫다
> - **Vercel**: Spring Boot 같은 장기 실행 Java 서버를 애초에 올릴 수 없다. React를 제거해 배포할 정적 프론트엔드도 없다
> - **Heroku·Railway 무료 티어**: 사실상 사라졌거나 크레딧 소진형이다

---

### 배포 전에 반드시 바꿔야 하는 것 3가지

무료냐 아니냐보다 **이쪽이 실제 작업량**이다. 세 가지를 안 고치면 배포해도 정상 동작하지 않는다.

| | 항목 | 상태 |
|---|---|---|
| ① | H2 → 외부 PostgreSQL | ⬜ 배포 시 작업 |
| ② | `PORT` 환경변수 대응 | ✅ **적용 완료** |
| ③ | 세션 쿠키 `secure: true` | ⬜ 배포 시 작업 (운영 프로파일) |

#### ① H2 → 외부 PostgreSQL (가장 중요)

Cloud Run은 요청이 없으면 컨테이너를 종료한다. **H2 인메모리를 그대로 쓰면 컨테이너가 내려가는 순간 가입한 회원과 게시글이 전부 사라진다.**

`build.gradle`에 PostgreSQL 드라이버 추가:

```gradle
runtimeOnly 'org.postgresql:postgresql'
```

`src/main/resources/application-prod.yml` 신규 생성:

```yaml
spring:
  datasource:
    url: ${DB_URL}          # 예: jdbc:postgresql://db.xxx.supabase.co:5432/postgres
    username: ${DB_USER}
    password: ${DB_PASSWORD}
  jpa:
    hibernate:
      ddl-auto: validate    # 운영에서 create-drop은 절대 금지 — 재시작마다 데이터가 날아간다
    database-platform: org.hibernate.dialect.PostgreSQLDialect
  h2:
    console:
      enabled: false        # 운영에서 H2 콘솔을 열어두지 않는다
```

> DB 비밀번호는 **환경변수로만** 주입한다. 코드나 설정 파일에 절대 하드코딩하지 않는다.
> `application-prod.yml`이 저장소에 올라가더라도 실제 값은 들어있지 않아야 한다.

#### ② 포트를 `PORT` 환경변수에서 읽기 — ✅ **적용 완료 (2026-08-20)**

Cloud Run은 컨테이너에 `PORT` 환경변수를 주입하고, 앱은 **그 포트로 들어야 한다.**

`application.yml`에 이미 반영되어 있다:

```yaml
server:
  port: ${PORT:8080}    # 배포 환경이 주입하는 PORT를 쓰되, 로컬에서는 8080
```

**확인한 것**: `PORT` 없이 실행하면 8080, `PORT=9090`으로 실행하면 9090에서 응답하고 8080은 비어 있다.

> `PORT`를 직접 설정하지 말 것 — 플랫폼이 정하는 값이다.

#### ③ 세션 쿠키에 `secure` 켜기

배포하면 HTTPS가 자동으로 적용된다. 그때 `application-prod.yml`에 추가:

```yaml
server:
  servlet:
    session:
      cookie:
        secure: true      # HTTPS 전용
        http-only: true
        same-site: lax
```

로컬(`http`)에서 켜면 쿠키가 전송되지 않아 **로그인이 되지 않는다.** 그래서 운영 프로파일에만 둔다.

### 배포 절차

#### 2-1. 빌드 방식 — Java 17을 명시해야 한다

`gcloud run deploy --source .`는 Dockerfile 없이 버들팩으로 빌드해준다. 다만 **버들팩의 기본 Java 버전이 낮아** 그대로 두면 빌드가 깨진다. 프로젝트 루트에 `project.toml`을 만든다:

```toml
[[build.env]]
name = "GOOGLE_RUNTIME_VERSION"
value = "17"
```

> Dockerfile을 직접 쓰고 싶다면 `./gradlew bootBuildImage`로 이미지를 만들어도 된다.
> 버들팩 쪽이 관리할 파일이 적어 이 프로젝트에는 더 맞는다.

#### 2-2. DB 준비 (Supabase)

1. Supabase 프로젝트 생성 → Settings → Database에서 **JDBC 연결 문자열** 확인
2. 스키마는 첫 배포 때 만든다 — `ddl-auto`를 일시적으로 `update`로 두고 한 번 띄운 뒤, **곧바로 `validate`로 되돌린다**
3. 로컬 H2 데이터는 옮길 필요 없다 (테스트 데이터일 뿐이다)

> **Supabase 무료 티어 주의**: 약 1주일간 접속이 없으면 프로젝트가 일시정지되고, 대시보드에서 수동으로 재개해야 한다.
> 포트폴리오 링크를 오래 방치했다가 면접 직전에 확인하는 상황이라면 이 점을 기억할 것.
> 이게 걸리면 **Neon**(서버리스 Postgres)이 Cloud Run의 스케일 투 제로와 궁합이 더 좋다.

#### 2-3. 배포

```bash
gcloud run deploy secure-bulletin-board \
  --source . \
  --region asia-northeast3 \
  --allow-unauthenticated \
  --max-instances 1 \
  --set-env-vars "SPRING_PROFILES_ACTIVE=prod" \
  --set-env-vars "DB_URL=jdbc:postgresql://...,DB_USER=...,DB_PASSWORD=..."
```

- `--allow-unauthenticated`: 누구나 접속 가능하게 한다 (공개 게시판이므로)
- `--max-instances 1`: **세션 인증이라 인스턴스가 늘면 세션이 흩어진다.** 포트폴리오 트래픽에서는 1개로 고정하는 편이 안전하다
- 비밀번호를 명령줄에 직접 넣기 싫다면 **Secret Manager**를 쓰고 `--set-secrets`로 주입한다

#### 2-4. 접속 주소 주의

`context-path: /api`이므로 **루트(`https://.../`)로 들어가면 404**가 뜬다. 실제 진입점은:

```
https://<서비스주소>/api/posts
```

포트폴리오에 링크를 걸 때 `/api/posts`까지 포함해야 한다.
루트로도 들어가게 하려면 `context-path`를 없애야 하는데, 그러면 Postman 콜렉션과 문서의 경로를 전부 바꿔야 하므로 **링크에 경로를 포함하는 편이 간단하다.**

---

### JVM 메모리

무료 티어는 메모리가 512MB~1GB인데 **JVM만 200-300MB를 쓴다.** Cloud Run 기본값(512MB)으로도 뜨지만, 여유를 두려면:

```bash
--memory 1Gi --set-env-vars "JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75"
```

메모리를 올리면 무료 한도(GB-초)를 더 빨리 소진하지만, 포트폴리오 수준의 트래픽에서는 문제되지 않는다.

## 배포 후 체크리스트

- [ ] `ddl-auto`가 `validate`인가 — `create-drop`이면 재시작마다 데이터가 사라진다
- [ ] DB 비밀번호가 코드·설정 파일이 아니라 환경변수(또는 Secret Manager)로만 들어가는가
- [ ] 세션 쿠키에 `secure: true`가 켜져 있는가
- [ ] H2 콘솔이 꺼져 있는가 (`spring.h2.console.enabled: false`)
- [ ] 로그인 → 글쓰기 → **타인 글 수정 차단(403)** 이 배포 환경에서도 동작하는가
- [ ] Postman 콜렉션을 Production 환경(`baseUrl`을 배포 주소로)으로 돌려 **39개 단언이 전부 통과**하는가
- [ ] 배포 URL에 대고 **ZAP 스캔을 다시** 돌렸는가 — HTTPS가 붙으면 로컬과 결과가 달라진다
- [ ] 포트폴리오 링크에 `/api/posts` 경로가 포함돼 있는가

> **CORS 설정은 필요 없다.** React를 제거해 브라우저가 다른 출처로 요청할 일이 없어졌다.
> 화면과 API가 같은 출처에서 서빙되므로 CORS를 열 이유가 없고, 열지 않는 편이 안전하다.
