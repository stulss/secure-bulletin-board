## 2단계: 배포 (필요해지면)

### 배포처 선택 — 무료로 가능하다

**결론부터: 카드 없이 배포하려면 Render 다.**

| 호스트 | 카드 등록 | Java | 특징 |
|---|---|---|---|
| **Render** | **불필요** | ✅ (Docker) | 15분 미사용 시 슬립, 재기동 30~60초. 무료 750시간/월 |
| Cloudtype | 불필요로 보임 | ✅ (템플릿) | 국내 서비스·한국어 문서. 매일 1회 중지. MySQL 없이 **MariaDB** 제공 |
| Google Cloud Run | **필수** ❌ | ✅ | 상시 무료·슬립 없음. 하지만 결제 계정(카드) 등록이 필요해 이번에 탈락했다 |
| Vercel · Netlify | 불필요 | ❌ **불가** | JVM 런타임이 없다. 가이드 71건을 전수 확인했고 Java 항목은 0건이었다 |

DB 는 **Supabase** 또는 **Neon**(둘 다 무료·카드 불필요), 혹은 Cloudtype 내장 DB 를 쓴다.
Supabase 는 1주일 미사용 시 프로젝트가 일시정지되어 수동 재개가 필요하다는 점만 기억할 것.

### 배포 전에 반드시 바꿔야 하는 것 3가지

무료냐 아니냐보다 **이쪽이 실제 작업량**이다. 세 가지를 안 고치면 배포해도 정상 동작하지 않는다.

| | 항목 | 현재 코드 상태 |
|---|---|---|
| ① | H2 → 외부 DB | ⬜ **제거됨** — 커밋 `b0a2025` 에 `application-prod.yml`·드라이버·스키마 SQL 이 있다 |
| ② | `PORT` 환경변수 대응 | ✅ **남아 있음** (`application.yml`) |
| ③ | 세션 쿠키 `secure: true` | ⬜ **제거됨** — `prod` 프로파일과 함께 빠졌다 |

> **배포를 재개한다면** `git show b0a2025` 로 당시 설정을 꺼내 되살리는 것이 가장 빠르다.
> 아래 내용은 그때 실제로 만들고 검증했던 것을 그대로 옮겨 둔 기록이다.

### 운영 프로파일 (`application-prod.yml`)

`SPRING_PROFILES_ACTIVE=prod` 로 활성화된다. 로컬 개발은 기존 H2 그대로이므로 영향이 없다.

| 설정 | 값 | 이유 |
|---|---|---|
| `ddl-auto` | `validate` | 엔티티와 실제 테이블이 어긋나면 기동을 거부한다. 스키마가 조용히 틀어진 채 도는 것을 막는다 |
| `open-in-view` | `false` | 뷰 렌더링 중 DB 커넥션을 붙잡지 않는다 |
| `h2.console.enabled` | `false` | 열어두면 스키마와 데이터를 웹으로 노출하는 셈이다 |
| 세션 쿠키 | `secure` + `HttpOnly` + `SameSite=Lax` | HTTPS 전용. 로컬(http)에서 켜면 로그인이 안 되므로 prod 에만 둔다 |
| `server.error.*` | 스택 트레이스·메시지 숨김 | 오류 화면으로 내부 구조가 새지 않게 한다 |
| 로그 레벨 | `WARN` (Security 포함) | 운영에서 Security 디버그 로그는 인증 관련 내부 정보를 남긴다 |

**드라이버와 방언은 고정하지 않았다.** Spring Boot 가 JDBC URL 로 드라이버를, 커넥션 메타데이터로 방언을 알아낸다.
덕분에 **PostgreSQL 과 MySQL 중 무엇을 붙이든 설정 파일을 고칠 필요가 없다.**

> ⚠️ 그래서 `application.yml`(로컬)에서도 `driver-class-name`·`database-platform` 을 **지정하면 안 된다.**
> 지정하면 그 값이 prod 에도 남아 PostgreSQL URL 에 H2 드라이버를 물리려다 기동이 실패한다. 실제로 이 문제를 겪고 제거했다.

### DB 선택 — PostgreSQL vs MySQL

둘 다 지원하며 드라이버가 모두 포함돼 있다. 이 프로젝트는 테이블 2개에 특별한 기능을 쓰지 않아 **어느 쪽이든 동작에 차이가 없다.**

| | 선택 이유 |
|---|---|
| **MySQL / MariaDB** | 국내 채용 공고·국비 교육에서 압도적으로 많이 쓰인다. 단 **Cloudtype 은 MySQL 없이 MariaDB 만 제공**하므로 `mariadb-java-client` 드라이버와 `jdbc:mariadb://` 스킴을 쓴다 |
| **PostgreSQL** | 기획 단계에서 정했던 방향(Supabase 전제). 표준 SQL 준수도가 높다 |

스키마 파일은 양쪽 다 만들어 두었고, 지금은 커밋 `b0a2025` 안에 있다:

- `src/main/resources/db/schema-postgres.sql`
- `src/main/resources/db/schema-mysql.sql` (**MariaDB 에도 그대로 쓸 수 있다** — MariaDBDialect 로 생성한 DDL 과 한 글자도 다르지 않음을 확인했다)

두 파일 모두 **손으로 쓴 것이 아니라 엔티티에서 Hibernate 가 생성한 DDL** 이다.
엔티티를 고쳤다면 스키마도 다시 생성해야 `validate` 가 통과한다 — 생성 방법은 이 문서 맨 아래 "스키마 재생성" 참고.

### 검증한 것 (2026-08-20)

설정만 써두고 끝내지 않고 실제로 확인했다.

| 확인 | 결과 |
|---|---|
| `PORT` 미설정 / `PORT=9090` | 각각 8080·9090 에서 응답, 반대쪽 포트는 비어 있음 |
| `prod` + `jdbc:postgresql://...` | **PostgreSQL 드라이버** 선택됨 (`PSQLException` — DB 미존재로 연결 거부) |
| `prod` + `jdbc:mysql://...` | **MySQL 드라이버** 선택됨 (`CommunicationsException`) |
| 로컬 기본 프로파일 | H2 로 정상 기동, `/api/posts` 200 |
| 회귀 | JUnit 36건 · Postman 39개 단언 전부 통과 |

## Cloudtype 배포 절차

> 아래는 Cloudtype 기준이다. Cloud Run 으로 갈 경우의 절차는 이 문서 뒤쪽에 남겨두었다.

### 3-1. 사전 조건

- GitHub 저장소: **https://github.com/stulss/secure-bulletin-board** (`main`, `v0.0.1` 브랜치 push 완료)
- `gradlew` 실행 권한이 `100755` 로 등록돼 있어야 한다 (등록 완료). 빠지면 리눅스 빌드가 `Permission denied` 로 실패한다
- `gradle/wrapper/gradle-wrapper.jar` 가 커밋돼 있어야 한다 (커밋 완료). `.gitignore` 의 `*.jar` 에 걸리기 쉬우니 주의

### 3-2. DB 먼저 배포한다

앱보다 DB를 먼저 띄워야 앱이 기동할 때 붙을 대상이 있다.

1. 시작하기 → **데이터베이스** 카테고리 → **PostgreSQL** 또는 **MariaDB** 선택
   (MySQL 은 목록에 없다. 검색하면 phpMyAdmin 이 같이 나오는데 그건 DB 가 아니라 관리 도구이니 고르지 말 것)
2. **설정변경** → Root Password 지정
3. **배포하기**
4. 서비스명을 기억해 둔다 — 예: `postgresql-prod`. 이게 곧 내부 호스트명이 된다

**스키마를 한 번 만들어 준다.** 운영 프로파일이 `ddl-auto: validate` 라 테이블이 없으면 앱이 기동하지 않는다.
Cloudtype 대시보드의 DB 접속 도구나 외부 클라이언트로 접속해 아래를 실행한다.

- PostgreSQL → `src/main/resources/db/schema-postgres.sql`
- MySQL → `src/main/resources/db/schema-mysql.sql`

### 3-3. 앱 배포

시작하기 → **Spring Boot** 템플릿 → GitHub 저장소 `secure-bulletin-board` 선택.

| 설정 항목 | 값 |
|---|---|
| 브랜치 | `main` |
| JDK 버전 | **17** (`build.gradle` 과 일치해야 한다) |
| 빌드 명령어 | `./gradlew clean bootJar` |
| 시작 명령어 | `java -jar build/libs/secure-bulletin-board-1.0.0.jar` |
| 포트 | `8080` |

> ⚠️ 빌드 산출물이 두 개 나온다. `-plain.jar`(0.1MB)을 고르면 `no main manifest attribute` 로 죽는다.
> 실행 가능한 쪽은 `secure-bulletin-board-1.0.0.jar`(약 58MB)다.

### 3-4. 환경변수

앱 서비스의 **환경 변수** 항목에 넣는다. 비밀번호를 코드나 설정 파일에 쓰지 않는 이유가 이것이다.

```
SPRING_PROFILES_ACTIVE = prod
DB_USER                = postgres
DB_PASSWORD            = (3-2에서 정한 Root Password)
DB_URL                 = jdbc:postgresql://postgresql-prod:5432/postgres
```

MySQL 을 쓴다면:

```
DB_URL = jdbc:mysql://mysql-prod:3306/bulletin?serverTimezone=Asia/Seoul
DB_USER = root
```

`postgresql-prod` / `mysql-prod` 는 **3-2에서 정한 DB 서비스명**이다. 같은 프로젝트 안에서는 이 이름으로 내부망 통신이 되고, DB 를 외부에 노출하지 않아도 된다.

### 3-5. 접속 확인

`context-path: /api` 때문에 **루트로 들어가면 404** 다. 실제 진입점은:

```
https://<배포도메인>/api/posts
```

포트폴리오에 링크를 걸 때 `/api/posts` 까지 포함할 것.

### 3-6. 무료 플랜에서 알아둘 것

- **매일 1회 자동 중지**된다. 앱은 다시 띄우면 되고, **DB 데이터는 중지·재배포에도 유지**된다(공식 문서 명시)
- 다만 **자동 백업이 없다.** DB 서비스를 삭제하면 데이터도 영구히 사라진다
- 무료 메모리 1GB 를 앱(JVM 200~300MB)과 DB 가 나눠 쓴다. 기동에 실패하면 이 부분을 먼저 의심할 것

## 참고: 스키마 재생성

엔티티를 고치면 `ddl-auto: validate` 가 기동을 거부한다. 그때 스키마 SQL 을 다시 만든다.
손으로 고치지 말고 아래처럼 Hibernate 가 생성하게 할 것 — 손으로 쓰면 미묘하게 어긋나서 `validate` 가 계속 실패한다.

`src/test/java/com/securitybulletin/SchemaExportTest.java` 를 임시로 만들어 실행한다.

```java
@SpringBootTest
@TestPropertySource(properties = {
    "spring.jpa.hibernate.ddl-auto=none",
    "spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect",  // 또는 MySQLDialect
    "spring.jpa.properties.jakarta.persistence.schema-generation.scripts.action=create",
    "spring.jpa.properties.jakarta.persistence.schema-generation.scripts.create-target=build/schema-postgres.sql",
    "spring.jpa.properties.hibernate.hbm2ddl.delimiter=;"
})
class SchemaExportTest {
    @Test void exportSchema() { }   // 컨텍스트가 뜨는 것만으로 스크립트가 생성된다
}
```

```bash
./gradlew test --tests "com.securitybulletin.SchemaExportTest"
```

`build/schema-*.sql` 이 생성되면 `src/main/resources/db/` 로 옮기고, **임시 테스트는 지운다.**

## 부록: Google Cloud Run 으로 배포할 경우

Cloudtype 대신 Cloud Run 을 쓰면 매일 중지가 없다. 대신 설정이 조금 더 필요하다.

### 빌드 방식 — Java 17을 명시해야 한다

`gcloud run deploy --source .`는 Dockerfile 없이 버들팩으로 빌드해준다. 다만 **버들팩의 기본 Java 버전이 낮아** 그대로 두면 빌드가 깨진다. 프로젝트 루트에 `project.toml`을 만든다:

```toml
[[build.env]]
name = "GOOGLE_RUNTIME_VERSION"
value = "17"
```

> Dockerfile을 직접 쓰고 싶다면 `./gradlew bootBuildImage`로 이미지를 만들어도 된다.
> 버들팩 쪽이 관리할 파일이 적어 이 프로젝트에는 더 맞는다.

#### 2-2. DB 준비 (Supabase 또는 Neon)

1. 프로젝트 생성 → **JDBC 연결 문자열** 확인
2. `src/main/resources/db/schema-postgres.sql` 을 한 번 실행해 테이블을 만든다
3. 로컬 H2 데이터는 옮길 필요 없다 (테스트 데이터일 뿐이다)

> **Supabase 무료 티어 주의**: 약 1주일간 접속이 없으면 프로젝트가 일시정지되고, 대시보드에서 수동으로 재개해야 한다.
> 포트폴리오 링크를 오래 방치했다가 면접 직전에 확인하는 상황이라면 이 점을 기억할 것.
> 이게 걸리면 **Neon**(서버리스 Postgres)이 Cloud Run의 스케일 투 제로와 궁합이 더 좋다.

#### 2-3. 배포

```bash
gcloud run deploy secure-bulletin-board \
  --source . \
  --region asia-northeast3 \
  --allow-unauthenticated \
  --max-instances 1 \
  --set-env-vars "SPRING_PROFILES_ACTIVE=prod" \
  --set-env-vars "DB_URL=jdbc:postgresql://...,DB_USER=...,DB_PASSWORD=..."
```

- `--allow-unauthenticated`: 누구나 접속 가능하게 한다 (공개 게시판이므로)
- `--max-instances 1`: **세션 인증이라 인스턴스가 늘면 세션이 흩어진다.** 포트폴리오 트래픽에서는 1개로 고정하는 편이 안전하다
- 비밀번호를 명령줄에 직접 넣기 싫다면 **Secret Manager**를 쓰고 `--set-secrets`로 주입한다

#### 2-4. 접속 주소 주의

`context-path: /api`이므로 **루트(`https://.../`)로 들어가면 404**가 뜬다. 실제 진입점은:

```
https://<서비스주소>/api/posts
```

포트폴리오에 링크를 걸 때 `/api/posts`까지 포함해야 한다.
루트로도 들어가게 하려면 `context-path`를 없애야 하는데, 그러면 Postman 콜렉션과 문서의 경로를 전부 바꿔야 하므로 **링크에 경로를 포함하는 편이 간단하다.**

### JVM 메모리

무료 티어는 메모리가 512MB~1GB인데 **JVM만 200-300MB를 쓴다.** Cloud Run 기본값(512MB)으로도 뜨지만, 여유를 두려면:

```bash
--memory 1Gi --set-env-vars "JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75"
```

메모리를 올리면 무료 한도(GB-초)를 더 빨리 소진하지만, 포트폴리오 수준의 트래픽에서는 문제되지 않는다.

- [ ] 로그인 → 글쓰기 → **타인 글 수정 차단(403)** 이 배포 환경에서도 동작하는가
